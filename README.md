# Resume Tailor

把 JD 翻译成“真实岗位工作内容”，再基于你的真实经历生成“针对这个岗位的简历定制方案”。

Resume Tailor 不是简单的“AI 润色简历工具”，而是一个帮助你判断“这个岗位到底在做什么、我是否值得投、简历里哪些经历该删/改/补”的求职工作台。

## 它解决什么问题

很多人投简历时的核心问题，不是“字写得不够好”，而是：

- JD 里写的术语、空话和岗位描述看起来很像，但实际并不等于真实工作
- 一份简历能通用很多岗位，但不能真正“对上”某个岗位
- 海投的成本很高，但逐个岗位手动改简历又太贵
- 很多工具只会给你“润色后的词”，却不会告诉你“这个岗位实际上看重什么”

Resume Tailor 的思路是：先理解岗位，再判断简历是否匹配，再做定制化修改，而不是直接生成一份“看起来更高级”的全文。

## 核心价值

### 1. 先读懂 JD，别被招聘话术骗

系统会把 JD 拆成几个关键层面：

- 岗位定性：职位族、级别、工作性质、主要产出物
- 团队画像：这个岗位挂在哪个团队、服务对象是谁、为什么存在
- 职责翻译：把抽象职责还原成真实工作场景
- 交互画像：这个岗位每天常和谁打交道，沟通属性是什么
- 典型工作日：岗位日常会怎么运作
- 机器筛规则：哪些是硬门槛，哪些只是加分项
- 误读风险：这个岗位最容易被误解成什么，误投的代价是什么

这样你不是看“JD 写了什么”，而是看“这个岗位真实在做什么”。

### 2. 不是给词，而是判断匹配

系统不会伪造一个看似精确的百分比，而是给出更实用的定性判断：

- A：值得投
- B：改后投
- C：观望
- D：不建议投

并且会标出每个关键要求是：

- met：有现成证据
- partial：有相近经历但没有写到位
- gap：当前简历和素材库都没有证据

这样你可以直接判断：这是措辞问题，还是主线不对，还是根本不匹配。

### 3. 定制简历，不是全文重写

Resume Tailor 的修改策略分三档：

- 措辞微调：方向基本对口，只是想法没说清
- 换主线：方向相近，但主线不对，需要重排经历
- 大改重构：删无关经历，补真实素材，重新组织主线

重点是：
- 删无关
- 改相关
- 补缺口

而不是“一次性生成一份看起来更像目标岗位的全文”。

### 4. 用户确认每一条修改

修改方案是逐条 diff，而不是一次性输出整份大改稿：

- 每条修改都附带原因
- 可勾选/取消
- 可编辑
- 可按用户要求只重写某一条
- 应用后可查看 applied / skipped 结果
- 可检查核心关键词覆盖率

这种设计让 AI 更像“建议与校验工具”，而不是“黑盒重写器”。

### 5. 简历定制延伸到投后

生成修改之后，还支持投递追踪与面试准备：

- 记录投递状态
- 生成下一轮面试的准备
- 项目下钻卡
- likely questions
- gap 防御卡
- 60 秒自我介绍
- 面试前 checklist

也就是说，它不仅能“改简历”，还能帮你“过关”。

## 主要功能

- JD 五层解构：真实岗位画像 + 团队画像 + 要求排序 + 交互对象 + 典型工作日
- A/B/C/D 判定：判断岗位是否值得投
- 差距清单：硬门槛、加分项、核心词、关键缺口
- 分级修改方案：微调 / 换主线 / 重构
- diff 确认：逐条编辑、重写、拒绝
- 素材库与隐藏经历池：补足真实但未写在简历上的经历
- 支持 HTML / PDF 导入
- 投递看板与面试准备
- 浏览器本地存储，服务端不做数据库

## 工作流

1. 上传或选择一份简历
2. 粘贴目标 JD
3. 系统先解析岗位真实在做什么
4. 对照简历现状，判断是否值得投
5. 生成改简历方案
6. 用户逐条确认和编辑
7. 应用修改并验证关键词覆盖
8. 保存为该岗位专用版本
9. 记录投递状态并生成面试准备

## 为什么它和“直接贴 JD 给 ChatGPT”不一样

传统做法常见问题：

- 直接贴 JD 给 AI，AI 往往只会“润色措辞”
- 缺少岗位真实信息的还原
- 没有判断哪些要求是硬门槛
- 没有区分“措辞问题”和“主线问题”
- 容易生成一份看起来凑合但并不真的对上岗位的简历

Resume Tailor 的关键区别在于：

- 先理解 JD
- 再判断差距
- 再决定删、改、补
- 最后才落成简历内容

它不是“AI 帮你改一句话”，而是“帮你把岗位理解透，用真实证据定制简历”。

## 输入方式

Resume Tailor 支持两种主流输入方式：

- HTML：主链路，适合长期维护和逐条精确编辑
- PDF：兼容入口，适合导入已有 PDF 简历后进行结构化解析

HTML 是更适合��期定制的格式，因为它允许精确定位文本节点，逐条替换并保留原版式；PDF 更像“导入旧简历”的补充入口。

## 快速开始

```bash
git clone <repo-url> && cd resume-tailor
npm install
npm run start
```

打开本地页面后，按下面流程使用：

1. 上传简历（HTML 或 PDF）
2. 粘贴目标 JD
3. 进入分析页面
4. 确认岗位判断和差距清单
5. 生成修改方案
6. 逐条确认与应用
7. 下载或预览最终版本

## 架构概览

```text
public/
  index.html          页面结构与向导入口
  app.js              前端交互、状态管理、PDF 解析、diff 与预览
  style.css           样式

src/
  server.ts           Express / Vercel API
  analyze.ts          LLM 分析与结构化输出
  prompts.ts          JD 解构、筛选判断、编辑策略、面试 prep prompts
  apply.ts            HTML 文本节点定位和精确替换
  structuredApply.ts  结构化简历的按下标修改逻辑
  api/index.ts        Vercel 入口

storage/
  IndexedDB          浏览器本地存储，保存简历、素材、投递记录和配置
```
